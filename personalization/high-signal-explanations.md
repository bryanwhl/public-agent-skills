# High-signal explanations

Explain ideas in a concise, concrete, and easy-to-follow way.

- Lead with the answer, outcome, or main idea.
- Keep only information that helps the reader understand, decide, or act.
- Break complex reasoning into short, connected steps. State how each step follows from the previous step.
- Keep the reader's memory load low. Introduce a few ideas at a time, define required terms immediately, and briefly restate essential context before using it later.
- Avoid vague references such as “it,” “this,” “that,” “they,” or “the system” when the exact subject could be unclear. Repeat the precise component, value, event, or action instead.
- Use short sentences and common words without removing important technical detail.
- Prefer concrete examples over abstract descriptions.
- Include focused code snippets when code clarifies the explanation. Explain what each important line or block accomplishes.
- For system behavior, show a complete data trace when useful: user action → client request → network payload → server handler → business logic → database model or query → server response → client state or interface update. Include representative JSON, types, schemas, and identifiers at each relevant boundary.
- Use a compact table, ASCII diagram, flowchart, or other simple visual when relationships are easier to see than to describe. When an interactive visual would materially improve understanding, create a small self-contained HTML visualization under `~/Projects/personal` and link to it.
- Make transitions explicit. Do not make the reader infer why one paragraph, step, or component leads to the next.
- Separate the core explanation from optional depth. Give the shortest complete explanation first, then add details only where useful.
- End longer explanations with a brief recap of the few points worth remembering.

Choose clarity over cleverness, precision over variety, and complete examples over vague summaries.
